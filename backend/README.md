# KrishiSetu Backend

FastAPI service backing the marketplace, escrow order flow, mocked voice-listing
AI, and cold-storage routing.

## Run locally

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

API runs at http://localhost:8000
Interactive docs (auto-generated by FastAPI) at http://localhost:8000/docs

## Run with Docker

```bash
cd backend
docker build -t krishisetu-backend .
docker run -p 8000:8000 krishisetu-backend
```

Or via the root `docker-compose.yml`, which runs frontend + backend together:

```bash
docker compose up --build
```

## Notes for the demo

- **Data store is in-memory** — resets on every restart, not thread-safe. Fine
  for a hackathon demo; swap for Postgres/Mongo before treating this as
  production.
- **Voice AI endpoint is mocked** — `/api/ai/voice-to-listing` always returns
  the same sample extraction regardless of input audio. Wire up a real
  speech-to-text/NLP service before claiming live voice parsing.
- **CORS is locked to localhost:5173** — add your deployed frontend URL (e.g.
  the Vercel domain) to `allow_origins` in `main.py` before demoing against a
  live-hosted frontend.
- **Order status transitions are forward-only** (see `ALLOWED_TRANSITIONS`) —
  an order can't skip straight to `funds_released` or be revived after
  `cancelled`.

## API endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/listings` | List all produce listings |
| GET | `/api/listings/{id}` | Get one listing |
| POST | `/api/listings` | Create a new listing |
| DELETE | `/api/listings/{id}` | Remove a listing |
| GET | `/api/orders` | List all orders |
| GET | `/api/orders/{id}` | Get one order |
| POST | `/api/orders` | Place an order (locks escrow) |
| PATCH | `/api/orders/{id}/status` | Advance order status |
| POST | `/api/ai/voice-to-listing` | Mocked voice → listing extraction |
| GET | `/api/logistics/nearest-cold-storage` | Nearest cold-storage node by lat/lng |
